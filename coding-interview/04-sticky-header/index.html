    4. Sticky Header & Sticky Table Header¶

    L1 ★★☆ · position: sticky, scroll containers, scroll-padding-top

    Problem¶

    Make the site header stay visible while scrolling, make a table's header row stay visible inside its own scrollable box, and make in-page anchor links land below the sticky header instead of underneath it.

    Key idea¶

    position: sticky; top: 0 behaves like relative until its scroll container scrolls it to top: 0, then it sticks. The nearest scrolling ancestor is the reference, so the same declaration on th sticks inside .scroll, not the page. scroll-padding-top on html offsets anchor jumps and scrollIntoView by the header's height.

    flowchart TB V["viewport scrolls"] --> H["header: sticky, top 0 → pinned to the viewport"] S[".scroll box scrolls"] --> T["th: sticky, top 0 → pinned inside the box"] A["#faq link / scrollIntoView"] --> P["html { scroll-padding-top: 56px } → lands below the header"]

    Solution¶

    04-sticky-header.html
    <!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Sticky header and sticky table header</title>
<style>
  :root { font-family: system-ui, sans-serif; }
  body { margin: 0; }
  .site-header {
    position: sticky; top: 0; z-index: 10;            /* sticks once it reaches the top of the viewport */
    background: rgb(255 255 255 / .9); backdrop-filter: blur(8px);
    border-bottom: 1px solid #e2e8f0; padding: 12px 16px; font-weight: 700;
  }
  main { padding: 16px; }
  .scroll { max-height: 240px; overflow: auto; border: 1px solid #e2e8f0; border-radius: 8px; }
  table { border-collapse: separate; border-spacing: 0; width: 100%; }
  th { position: sticky; top: 0; background: #eef2ff; text-align: left; }   /* sticky inside the scroll container */
  th, td { padding: 8px 12px; border-bottom: 1px solid #e2e8f0; }
  /* Jump links land BELOW the sticky header instead of under it */
  html { scroll-padding-top: 56px; }
</style>
</head>
<body>
  <header class="site-header">Acme Store</header>
  <main>
    <div class="scroll" tabindex="0" aria-label="Orders table">
      <table>
        <thead><tr><th scope="col">Order</th><th scope="col">Status</th></tr></thead>
        <tbody id="rows"></tbody>
      </table>
    </div>
    <div style="height: 2000px"></div>
    <h2 id="faq">FAQ</h2>
  </main>
  <script>
    document.getElementById("rows").innerHTML =
      Array.from({ length: 30 }, (_, i) => `<tr><td>A-${i + 1}</td><td>${i % 3 ? "Shipped" : "Placed"}</td></tr>`).join("");
  </script>
</body>
</html>

    Live demo¶

    Open it full-size: 04-sticky-header.html. Resize the window to watch it respond.

    Walkthrough¶

    Code Why
    .site-header { position: sticky; top: 0; z-index: 10; } top is required: sticky does nothing without an offset. z-index keeps it above content that scrolls under it.
    background: rgb(255 255 255 / .9); backdrop-filter: blur(8px); A frosted header: content stays readable as it scrolls underneath.
    th { position: sticky; top: 0; } Sticky inside .scroll because that's the nearest scroll container. border-collapse: separate avoids rendering glitches with sticky cells.
    html { scroll-padding-top: 56px; } Without it, #faq scrolls under the header. The check verifies the heading lands below it.
    .scroll { tabindex=0 aria-label=… } A scrollable region must be focusable so keyboard users can scroll it, and labelled so screen readers announce it.

    Complexity¶

    Approach Time Space
    scrolling composited by the browser -

    Run it¶

    cd coding-interview && npm test   # runs every check; this problem's report is below

    04-sticky-header: 3 checks, 0 failures
  ✔ site header stays at the top after scrolling 1000 px
  ✔ table header sticks inside its own scroll container
  ✔ jump links land below the header (scroll-padding-top)

    Common mistakes¶

    • overflow: hidden (or auto) on an ancestor. That ancestor becomes the scroll container, and sticky silently stops working on the page.
    • Forgetting top: 0.
    • Using position: fixed plus a hard-coded padding-top on the body. The header leaves the flow and the padding gets out of sync with its height.
    • Scroll listeners that toggle classes on every scroll event, which causes jank. Use sticky, or IntersectionObserver for "is it stuck?" styling.

    Follow-up questions¶

    How do you style the header differently once it's stuck?

    Put a 1 px sentinel just above the header and observe it with IntersectionObserver. When the sentinel leaves the viewport, add a .stuck class (for example to add a shadow). Scroll-driven animations (animation-timeline: scroll()) can also do it in pure CSS.

    Why might sticky not work inside a flex or grid parent?

    If the sticky item stretches to the full height of its parent (the default align-items: stretch), there's no room to stick. Give it align-self: start.
