    10. Promise.all, allSettled & a Concurrency Pool¶

    L2 ★★☆ · Promise construction, input order, first rejection, async worker pool

    Problem¶

    Implement promiseAll and promiseAllSettled without the built-ins, and a pool(tasks, limit) that runs async tasks with at most limit in flight, returning results in input order.

    Key idea¶

    all creates one outer promise, subscribes to every input (wrapped in Promise.resolve so plain values and thenables work), stores each result at its index, and resolves when the countdown reaches zero, or rejects on the first rejection. allSettled maps every input to an outcome object, then reuses all. A pool starts limit workers that each pull the next index from a shared counter until the list is exhausted.

    flowchart LR T["12 tasks"] --> W1["worker 1: next++"] T --> W2["worker 2: next++"] T --> W3["worker 3: next++"] W1 & W2 & W3 --> R["results[i] = await tasks[i]() (input order)"] R --> D["promiseAll(workers) → done"]

    Solution¶

    promise-utils.mjs
    /** Problem 10: Promise.all and Promise.allSettled from scratch, plus a concurrency-limited pool. */

export function promiseAll(iterable) {
  return new Promise((resolve, reject) => {
    const items = [...iterable];
    const results = new Array(items.length);
    let remaining = items.length;
    if (remaining === 0) return resolve(results);        // all([]) resolves immediately
    items.forEach((item, i) => {
      Promise.resolve(item).then((value) => {            // Promise.resolve: plain values and thenables work too
        results[i] = value;                              // keep INPUT order, not completion order
        if (--remaining === 0) resolve(results);
      }, reject);                                        // first rejection wins; later ones are ignored
    });
  });
}

export function promiseAllSettled(iterable) {
  return promiseAll([...iterable].map((item) =>
    Promise.resolve(item).then(
      (value) => ({ status: "fulfilled", value }),
      (reason) => ({ status: "rejected", reason }))));
}

/** Run `tasks` (functions returning promises) with at most `limit` in flight; results in input order. */
export async function pool(tasks, limit) {
  const results = new Array(tasks.length);
  let next = 0;
  async function worker() {
    while (next < tasks.length) {
      const i = next++;                                  // single-threaded JS: no race on next++
      results[i] = await tasks[i]();
    }
  }
  await promiseAll(Array.from({ length: Math.min(limit, tasks.length) }, worker));
  return results;
}

    Walkthrough¶

    Code Why
    Promise.resolve(item).then((value) => { results[i] = value; if (--remaining === 0) resolve(results); }, reject) Index-based storage keeps input order even though completion order differs. Rejecting on the first failure matches the spec.
    if (remaining === 0) return resolve(results); all([]) must resolve immediately, a classic edge case.
    (value) => ({ status: "fulfilled", value }), (reason) => ({ status: "rejected", reason }) allSettled never rejects. Every input becomes a descriptive object, with the same shape as the built-in, and the check compares against it.
    const i = next++; results[i] = await tasks[i](); Safe without locks: JavaScript runs one piece of code at a time, and await is the only point where another worker can run.
    Array.from({ length: Math.min(limit, tasks.length) }, worker) Exactly limit workers. The check measures the maximum concurrency as 3.

    Complexity¶

    Approach Time Space
    promiseAll O(n) O(n)
    pool O(n) tasks, ≤ limit concurrent O(n) results

    Run it¶

    cd coding-interview && npm test   # runs every check; this problem's report is below

    10-promise-utils: 5 checks, 0 failures
  ✔ promiseAll keeps input order, not completion order
  ✔ promiseAll rejects with the first rejection; [] resolves immediately
  ✔ promiseAllSettled reports every outcome
  ✔ matches the built-ins on the same inputs
  ✔ pool never exceeds the limit and returns results in order

    Common mistakes¶

    • Pushing results with results.push(value), which gives completion order instead of input order.
    • Forgetting that inputs can be plain values, not only promises.
    • A "pool" that starts every task at once with tasks.map(t => t()) and only awaits them in batches. The concurrency isn't actually limited.
    • promiseAll that keeps running other work after a rejection and leaks errors as unhandled rejections. (The other promises still run; all just stops listening. Use AbortController to really cancel.)

    Follow-up questions¶

    Implement Promise.race and Promise.any.

    race: resolve or reject with the first settled input (items.forEach(p => Promise.resolve(p).then(resolve, reject))). any: resolve with the first fulfilled input. Reject only when all inputs reject, with an AggregateError of the reasons, counting down rejections the way all counts fulfilments.

    How do you add a timeout to a promise?

    Promise.race([p, new Promise((_, rej) => setTimeout(() => rej(new Error('timeout')), ms))]). For fetch, prefer AbortSignal.timeout(ms), which actually cancels the request instead of just ignoring it.
