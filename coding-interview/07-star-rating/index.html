    7. Star Rating with Zero JavaScript¶

    L2 ★★☆ · Radio inputs, row-reverse + ~, visually-hidden pattern, content: "★" / ""

    Problem¶

    Build a 5-star rating input. Hovering previews the rating, clicking sets it, it works with the keyboard and screen readers, it submits with a form, and it uses no JavaScript.

    Key idea¶

    Use radio inputs for the semantics: keyboard arrows, form value and screen-reader names all come for free. CSS can only select later siblings (~), so put the stars in DOM order 5→1 and display them with flex-direction: row-reverse. "Checked and all stars below it" then becomes input:checked ~ label. Hide the inputs visually (the clip pattern), never with display: none, hidden or a full-size opacity: 0.

    flowchart LR DOM["DOM order: s5 s4 s3 s2 s1"] --> RR["row-reverse → shows 1 2 3 4 5"] CK["s4:checked"] --> SIB["s4 ~ label → labels of s4, s3, s2, s1"] SIB --> LIT["4 stars lit"]

    Solution¶

    07-star-rating.html
    <!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Star rating (CSS only)</title>
<style>
  :root { font-family: system-ui, sans-serif; }
  body { margin: 0; padding: 24px; }
  /* Real radio inputs: keyboard (arrow keys), forms and screen readers work for free. No JavaScript. */
  .rating { border: 0; padding: 0; display: inline-flex; flex-direction: row-reverse; }   /* reversed so ~ selects LOWER stars */
  .rating legend { position: absolute; width: 1px; height: 1px; overflow: hidden; clip-path: inset(50%); }  /* visually hidden */
  .rating { position: relative; }
  /* Visually hidden but focusable. NOT opacity:0 at full size: invisible inputs stacked on the stars steal clicks. */
  .rating input { position: absolute; width: 1px; height: 1px; margin: 0; overflow: hidden; clip-path: inset(50%); }
  .rating label { font-size: 2rem; color: #cbd5e1; cursor: pointer; padding: 0 2px; }
  .rating label::before { content: "★" / ""; }                  /* "/ ''": decorative, not read aloud */
  .sr-only { position: absolute; width: 1px; height: 1px; overflow: hidden; clip-path: inset(50%); white-space: nowrap; }
  /* Checked star and every star after it in DOM order (= before it visually) light up */
  .rating input:checked ~ label { color: #f59e0b; }
  /* Hover preview overrides: hovered star and lower ones */
  .rating:hover label { color: #cbd5e1; }
  .rating label:hover, .rating label:hover ~ label { color: #fbbf24; }
  .rating input:focus-visible + label { outline: 3px solid #a5b4fc; border-radius: 4px; }
</style>
</head>
<body>
  <form id="review">
    <fieldset class="rating">
      <legend>Rate this product</legend>
      <input type="radio" id="s5" name="stars" value="5"><label for="s5"><span class="sr-only">5 stars</span></label>
      <input type="radio" id="s4" name="stars" value="4"><label for="s4"><span class="sr-only">4 stars</span></label>
      <input type="radio" id="s3" name="stars" value="3"><label for="s3"><span class="sr-only">3 stars</span></label>
      <input type="radio" id="s2" name="stars" value="2"><label for="s2"><span class="sr-only">2 stars</span></label>
      <input type="radio" id="s1" name="stars" value="1"><label for="s1"><span class="sr-only">1 star</span></label>
    </fieldset>
  </form>
</body>
</html>

    Live demo¶

    Open it full-size: 07-star-rating.html. Resize the window to watch it respond.

    Walkthrough¶

    Code Why
    .rating { flex-direction: row-reverse; } Visual order is reversed, so the sibling combinator selects the stars to the left of the checked one.
    .rating input:checked ~ label { color: #f59e0b; } The checked star and every later sibling (the lower ratings) light up. The check counts exactly 4 amber stars after clicking the 4th.
    .rating input { width: 1px; height: 1px; clip-path: inset(50%); } Bug found by the checks: the first draft used opacity: 0 at full size, and the five invisible inputs stacked over the first star and intercepted clicks. Clipping keeps them focusable without taking space.
    <span class="sr-only">4 stars</span> Bug found by the checks: the first draft used <span hidden>, which hides the text from screen readers too, so the radios had no names. The check asserts getByRole('radio', { name: '4 stars' }).
    content: "★" / ""; Alternative text for generated content. The decorative star isn't read aloud as "black star".

    07-star-rating: 3 checks, 0 failures
  ✔ clicking the 4th star checks 4 and lights up exactly 4 stars

    Common mistakes¶

    • display: none on the inputs, which removes them from the keyboard and accessibility tree. The rating becomes mouse-only.
    • Building it from <span>s with click handlers: no keyboard support, no form value, no semantics.
    • Forgetting a group label (<fieldset> + <legend>), so screen readers don't know what the stars rate.
    • Hover-only previews with no focus styling for keyboard users (:focus-visible + label).

    Follow-up questions¶

    How would you support half stars?

    Use ten radio inputs (0.5 steps) whose labels each cover half a star (clip-path or a half-width ::before), or use a native <input type="range" step="0.5"> styled as stars. The range input announces its value and supports arrow keys.

    How do you show a read-only average like 3.7?

    Don't use inputs. Render the text 3.7 out of 5 for assistive technology and draw the stars with a background gradient or mask whose width is calc(3.7 / 5 * 100%).
