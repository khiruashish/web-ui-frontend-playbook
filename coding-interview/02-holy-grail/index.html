    2. Holy Grail Layout with Grid Areas¶

    L1 ★★☆ · grid-template-areas, mobile first, 100dvh, source order

    Problem¶

    Build a page with a header, footer, left navigation, main content and right sidebar. On desktop the three columns sit side by side and the footer stays at the bottom even when the content is short. On mobile everything stacks in reading order.

    Key idea¶

    Name the regions with grid-template-areas, then redraw the "map" at each breakpoint. The HTML keeps semantic source order (header, nav, main, aside, footer), which is also the mobile and screen-reader order. min-height: 100dvh with a 1fr main row keeps the footer at the bottom without any position tricks.

    flowchart TB subgraph Desktop["≥ 900 px: 200px | 1fr | 240px"] direction LR H1["header (spans 3)"] N1[nav] --- M1[main] --- A1[aside] F1["footer (spans 3)"] end subgraph Mobile["< 900 px: one column"] direction TB H2[header] --> N2[nav] --> M2[main] --> A2[aside] --> F2[footer] end

    Solution¶

    02-holy-grail.html
    <!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Holy grail layout</title>
<style>
  :root { font-family: system-ui, sans-serif; }
  * { box-sizing: border-box; }
  body { margin: 0; }
  .page {
    min-height: 100dvh;                         /* dvh: correct on mobile with browser chrome */
    display: grid;
    grid-template:
      "header"  auto
      "nav"     auto
      "main"    1fr
      "aside"   auto
      "footer"  auto / 1fr;                     /* mobile first: one column, content order */
  }
  @media (min-width: 900px) {
    .page {
      grid-template:
        "header header header" auto
        "nav    main   aside"  1fr
        "footer footer footer" auto / 200px 1fr 240px;
    }
  }
  header { grid-area: header; background: #312e81; color: white; }
  nav    { grid-area: nav;    background: #e0e7ff; }
  main   { grid-area: main; }
  aside  { grid-area: aside;  background: #f1f5f9; }
  footer { grid-area: footer; background: #1e293b; color: white; }
  header, nav, main, aside, footer { padding: 16px; }
</style>
</head>
<body>
  <div class="page">
    <header>Header</header>
    <nav aria-label="Main">Navigation</nav>
    <main><h1>Main content</h1><p>Source order = reading order = mobile order. Only the grid template changes.</p></main>
    <aside>Sidebar</aside>
    <footer>Footer</footer>
  </div>
</body>
</html>

    Live demo¶

    Open it full-size: 02-holy-grail.html. Resize the window to watch it respond.

    Walkthrough¶

    Code Why
    grid-template: "header" auto "nav" auto "main" 1fr "aside" auto "footer" auto / 1fr; Mobile first: the single-column map is the source order.
    "header header header" auto "nav main aside" 1fr "footer footer footer" auto / 200px 1fr 240px The desktop map. Repeating a name makes an area span columns. The row sizes come before the /, the column sizes after.
    min-height: 100dvh; Dynamic viewport height accounts for mobile browser toolbars appearing and disappearing. 100vh can overflow on phones.
    header { grid-area: header; } ... Each element claims its area by name, and the CSS reads like a picture of the layout.
    check: footer bottom == viewport bottom (900 px) The sticky-footer behaviour is verified, as are the stacked order and full width at 400 px.

    02-holy-grail: 3 checks, 0 failures
  ✔ desktop: nav | main | aside in one row under a full-width header

  ✔ mobile: everything stacks in source order, full width

    Common mistakes¶

    • Reordering the DOM for the desktop design, or using order:/areas to put content in an illogical place. Keyboard and screen-reader order follow the DOM.
    • Fixed pixel heights on main or sidebar. Content overflows on small screens or large fonts.
    • Floats and calc(100% - 440px) for columns. Grid handles it with 200px 1fr 240px.
    • Forgetting <nav aria-label=…> and the landmark elements. They're how screen-reader users jump around the page.

    Follow-up questions¶

    Grid or Flexbox for page layout?

    Grid for two-dimensional layouts (rows and columns aligned together, such as page skeletons and dashboards). Flexbox for one-dimensional flows (a toolbar, a row of buttons, centring). They nest happily: the page uses grid, the header uses flex.

    How would you make the sidebar collapsible?

    Toggle a class on .page that changes grid-template-columns to 0 1fr 240px (or redraws the areas), and animate with transition: grid-template-columns, which modern browsers support. Keep the toggle a real <button aria-expanded>.
