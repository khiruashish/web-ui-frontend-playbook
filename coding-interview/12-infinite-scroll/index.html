    12. Infinite Scroll with IntersectionObserver¶

    L2 ★★★ · Sentinel + rootMargin, in-flight guard, DocumentFragment, end of feed

    Problem¶

    Load posts 20 at a time as the user scrolls, starting before they reach the bottom. Never fire two requests at once, stop at the end (75 posts), announce progress to screen readers, and avoid scroll listeners.

    Key idea¶

    Put an empty sentinel after the list and observe it with IntersectionObserver using rootMargin: "300px", so loading starts 300 px before it scrolls into view. A loading flag stops duplicate requests, a DocumentFragment appends a page in one reflow, and the observer disconnects at the end. Because the observer only fires on changes, check again after each load in case the sentinel is still visible (tall screens).

    sequenceDiagram participant IO as IntersectionObserver participant L as loadMore() participant API as fetchPage(offset) IO->>L: sentinel within 300 px L->>L: loading = true (guard) L->>API: offset 0 API-->>L: 20 posts L->>L: append fragment, loading = false L->>L: sentinel still visible? → loadMore() again IO->>L: user scrolls → next page … until < 20 returned → disconnect

    Solution¶

    12-infinite-scroll.html
    <!doctype html>
<html lang="en">
<head>
<meta charset="utf-8">
<meta name="viewport" content="width=device-width, initial-scale=1">
<title>Infinite scroll with IntersectionObserver</title>
<style>
  :root { font-family: system-ui, sans-serif; }
  body { margin: 0; padding: 16px; }
  #feed { list-style: none; padding: 0; margin: 0; display: grid; gap: 8px; }
  #feed li { padding: 24px 16px; border: 1px solid #e2e8f0; border-radius: 8px; }
  #status { text-align: center; padding: 16px; color: #64748b; }
</style>
</head>
<body>
  <ul id="feed" aria-label="Posts"></ul>
  <div id="sentinel" aria-hidden="true"></div>
  <p id="status" role="status">Loading…</p>
  <script>
    const PAGE = 20, TOTAL = 75;
    const feed = document.getElementById("feed"), status = document.getElementById("status"), sentinel = document.getElementById("sentinel");
    let next = 0, loading = false, done = false;

    // Fake API: 75 posts in pages of 20, 100 ms latency
    const fetchPage = (offset) => new Promise((r) => setTimeout(() =>
      r(Array.from({ length: Math.max(0, Math.min(PAGE, TOTAL - offset)) }, (_, i) => `Post #${offset + i + 1}`)), 100));

    async function loadMore() {
      if (loading || done) return;                       // guard: the observer can fire again while a request is in flight
      loading = true;
      const items = await fetchPage(next);
      const frag = document.createDocumentFragment();     // one reflow per page, not per item
      for (const text of items) { const li = document.createElement("li"); li.textContent = text; frag.append(li); }
      feed.append(frag);
      next += items.length;
      done = items.length < PAGE;
      status.textContent = done ? `All ${next} posts loaded` : `${next} posts loaded`;
      loading = false;
      if (done) { observer.disconnect(); return; }
      // IntersectionObserver only fires on CHANGES: if the sentinel is still on screen (tall viewport), keep loading
      if (sentinel.getBoundingClientRect().top < innerHeight + 300) loadMore();
    }

    // Fires when the sentinel comes within 300 px of the viewport: no scroll listeners, no layout thrashing
    const observer = new IntersectionObserver((entries) => { if (entries[0].isIntersecting) loadMore(); }, { rootMargin: "300px" });
    observer.observe(sentinel);
  </script>
</body>
</html>

    Live demo¶

    Open it full-size: 12-infinite-scroll.html. Resize the window to watch it respond.

    Walkthrough¶

    Code Why
    new IntersectionObserver(cb, { rootMargin: "300px" }) The browser computes visibility off the main thread. No scroll listener, no getBoundingClientRect on every scroll event.
    if (loading \|\| done) return; The observer can fire again while a request is in flight. Without the guard you get duplicate pages. The check asserts 75 unique posts.
    const frag = document.createDocumentFragment(); … feed.append(frag); One DOM insertion per page instead of 20, so a single layout.
    if (sentinel.getBoundingClientRect().top < innerHeight + 300) loadMore(); Bug found by the checks: on a 4000 px-tall screen the sentinel never left the viewport, so the observer never fired again and the feed stalled at 20. This re-check fixes it.
    <p id="status" role="status"> A live region: "40 posts loaded" and "All 75 posts loaded" are announced to screen-reader users.

    Complexity¶

    Approach Time Space
    per page O(page size) DOM work O(items rendered)

    Run it¶

    cd coding-interview && npm test   # runs every check; this problem's report is below

    12-infinite-scroll: 4 checks, 0 failures
  ✔ first page of 20 loads on open
  ✔ scrolling to the bottom loads the next page; never loads twice at once
  ✔ keeps going to the end: 75 unique posts, then stops
  ✔ a very tall screen keeps loading without any scroll (observer only fires on change)

    Common mistakes¶

    • window.addEventListener('scroll', …) measuring positions on every event, which causes jank and layout thrashing.
    • No in-flight guard, so the same page loads several times.
    • Never stopping, which fires empty requests forever at the end of the feed.
    • Keeping 10,000 DOM nodes. For very long feeds, virtualise (render only the visible window) and keep a "Load more" button as a fallback.

    Follow-up questions¶

    How do you keep the footer reachable and the back button working?

    Offer a "Load more" button instead of auto-loading after a few pages, or put the footer content elsewhere. Store the loaded page in the URL (?page=3) or history.state, and restore the scroll position on back navigation.

    Cursor or offset pagination for the API?

    Use a cursor (opaque next token from the last item). New posts inserted at the top then don't shift pages and cause duplicates or gaps, and deep pages stay fast on the database.
