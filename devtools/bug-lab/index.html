    Bug Lab: Find the 7 Bugs¶

    Beginner Intermediate

    This little FreshCart page has 7 bugs planted in it. Each one is the kind you'll meet every week, and each is best found with a different DevTools tool. Find them with DevTools, not by reading the source: the point is to practise the tools from Debugging with DevTools.

    Open the Bug Lab in a new tab and press F12 there. DevTools works best on a page of its own rather than inside this frame.

    Run it from a web server, not by double-clicking

    If you download the file and open it from disk (file://…), Chrome blocks fetch() completely and the Console says Fetch API cannot load file:///…/offer.json. URL scheme "file" is not supported. That hides bug 6. Serve the folder instead: VS Code's Live Server, or python3 -m http.server in the folder, then open http://localhost:8000/bug-lab.html.

    Each bug below has its symptom, the tool to reach for, and steps. Try it yourself, then open the answer. The fixes come from bug-lab-fixed.html, which is generated from the broken page by scripts/gen_bug_lab.py, so every fix shown here is exactly what runs there.

    Bug 1: the page scrolls sideways on a phone¶

    • Symptom: at phone width you can drag the whole page left and right, and there's a white strip on the right.

    • Tool: device toolbar + Elements (+ a Console snippet).

    • Press Ctrl+Shift+M (Cmd+Shift+M) and set the width to 375.

    • Paste the find-overflow snippet into the Console. It prints the culprit; hover the result to highlight it on the page.
    • Select it in Elements and look at Computed → width.
    Answer

    The promo banner has a fixed width: 420px, which is wider than a 375 px phone (343 px of room after padding):

    .promo {
  width: 420px;                     /* BUG 1 */
  margin: 0 0 16px;
  padding: 12px 16px;
  border-radius: 12px;
  background: #2563eb;
  color: #fff;
}

    Fix: let it be at most 420 px:

    max-width: 420px;                 /* FIX 1: may be up to 420px, but never wider than its container */

    Fixed widths are the most common cause of sideways scrolling. Prefer max-width, %, or min(420px, 100%).

    Bug 2: the price is grey, not green¶

    • Symptom: the CSS clearly says .price { color: #0c831f; }, but the prices are grey.

    • Tool: Elements → Styles.

    • Right-click a price → Inspect.

    • In Styles, find color: #0c831f under .price. Is it struck through?
    • Look above it for the rule that won, and hover both selectors to compare their specificity.
    Answer

    .card p has specificity (0,1,1) (one class + one element) and beats .price at (0,1,0) (one class), even though .price comes later in the file. Order only decides between equal specificities.

    .card p {
  margin: 4px 0 12px;
  color: #555;
}
.price {
  color: #0c831f;                   /* BUG 2: why is the price grey? */
  font-weight: 700;
}

    Fix: make the price rule more specific, (0,2,0):

    .card .price {                      /* FIX 2: (0,2,0) now beats .card p (0,1,1) */
  color: #0c831f;
  font-weight: 700;
}

    Don't reach for !important: it wins this fight but starts an arms race you'll lose later. See Cascade, Specificity & Box Model.

    Bug 3: the cards are in one column on a wide screen¶

    • Symptom: on a desktop, the three product cards are stacked in one tall column instead of sitting side by side.

    • Tool: Elements → grid badge + Styles.

    • Inspect the <div class="grid">. It has a grid badge: click it to draw the overlay. How many columns?

    • Look at its rules in Styles. One declaration has a warning icon.
    Answer

    A typo in the property name: grid-template-column (no s). Browsers silently ignore a property they don't know, so the grid falls back to one automatic column. DevTools shows it struck through with a warning icon ("Unknown property name").

    .grid {
  display: grid;
  grid-template-column: repeat(auto-fill, minmax(200px, 1fr));   /* BUG 3 */
  gap: 16px;
}

    grid-template-columns: repeat(auto-fill, minmax(200px, 1fr));  /* FIX 3: columns, with an s */

    Bug 4: all the badges pile up in the corner of the page¶

    • Symptom: "20% OFF", "NEW" and "FRESH" should sit on each card's picture. Instead they're stacked on top of each other near the top-left of the page.

    • Tool: Elements → Computed (on the badge and its ancestors).

    • Inspect a badge. Computed → position is absolute, with top: 8px; left: 8px. 8 px from what?

    • Select its parent .card. What is its position?
    Answer

    An absolutely positioned element is placed relative to its nearest positioned ancestor (one whose position isn't static). No card is positioned, so all three badges are placed relative to the page itself, at the same spot.

    .card {
  padding: 12px;
  border: 1px solid #e3e6ea;
  border-radius: 12px;
  background: #fff;
}
.badge {
  position: absolute;               /* BUG 4 */
  top: 8px;
  left: 8px;
  padding: 2px 8px;
  border-radius: 4px;
  background: #2563eb;
  color: #fff;
  font-size: 0.7rem;
  font-weight: 700;
}

    Fix: make each card the reference box:

    position: relative;               /* FIX 4: the badges are now positioned inside their card */

    Bug 5: clicking ADD shows an error¶

    • Symptom: click ADD. The cart badge stays at 0, and the Console turns red.

    • Tool: Console → Sources.

    • Open the Console. The error (captured from a real run in Chrome) reads:

      Uncaught TypeError: Cannot set properties of null (setting 'textContent')
    at HTMLDivElement.<anonymous> (bug-lab.html:125:53)

    • Click bug-lab.html:125 to jump to the line. Something on that line is null.

    • In the Console, run the selector from that line on its own: document.querySelector(".cart-count"). Then inspect the badge in Elements and compare its real class.
    Answer

    querySelector returns null when nothing matches, and you can't set textContent on null. The HTML uses class="cart-badge", but the script looks for .cart-count.

    document.querySelector(".grid").addEventListener("click", (event) => {
  const button = event.target.closest(".add");
  if (!button) return;
  const card = button.closest(".card");

  total = total + card.dataset.price;                           // BUG 7
  document.querySelector("#total").textContent = total;

  count++;
  document.querySelector(".cart-count").textContent = count;    // BUG 5
});

    document.querySelector(".cart-badge").textContent = count;    // FIX 5: the class in the HTML is cart-badge

    "Cannot read/set properties of null" almost always means a selector found nothing. Copy the selector into the Console to check it.

    Bug 6: “Couldn't load today's offer”¶

    • Symptom: the yellow strip says Couldn't load today's offer (HTTP 404) instead of the offer.

    • Tool: Network.

    • Open Network, filter to Fetch/XHR, and reload.

    • Find the red row. What URL did the page ask for? What's the status?
    • Compare it with the files that actually exist next to the page.
    Answer

    The page requests offer.json, but the file is called offers.json. The server answers 404 Not Found. The code handles that properly (it checks response.ok and shows a message), which is why there's no crash, only a wrong message.

    async function loadOffer() {
  const offer = document.querySelector("#offer");
  try {
    const response = await fetch("offer.json");                  // BUG 6
    if (!response.ok) throw new Error(`HTTP ${response.status}`);
    const data = await response.json();
    offer.textContent = `🔥 ${data.title}`;
  } catch (err) {
    offer.textContent = `Couldn't load today's offer (${err.message})`;
  }
}
loadOffer();

    const response = await fetch("offers.json");                 // FIX 6: the file is offers.json

    Bug 7: the total says ₹0189¶

    • Symptom: after one ADD on the apple (₹189), the total reads ₹0189. Add the banana and it becomes ₹018949. No error at all.

    • Tool: Sources → breakpoint + Watch.

    • In Sources, open bug-lab.html and put a breakpoint on the total = total + … line.

    • Click ADD. When it pauses, hover card.dataset.price. Are there quotes around the value?
    • Add typeof card.dataset.price to the Watch pane.
    Answer

    card.dataset.price is the string "189": data attributes are always strings. 0 + "189" joins text instead of adding, giving "0189". No error is thrown, so only stepping through and looking at the values shows the problem.

    total = total + Number(card.dataset.price);                   // FIX 7: data-* values are strings

    This is the same trap as "3" + 1 in JavaScript lesson 1. Better still for money: store whole paise (data-price="18900") as FreshCart does.

    All fixed¶

    Both pages are checked in a real browser on every change. The checks prove each bug really happens in the broken page and is gone in the fixed one, and run the console snippets from the guide against them:

    17-devtools-bug-lab: 6 checks, 0 failures
  ✔ bugs 1 and 3: the broken page scrolls sideways on a phone and its grid is one column; fixed: no scroll, 3 columns
  ✔ bugs 2 and 4: the price is grey and the badges pile up at the top of the page; fixed: green price, badges inside cards
  ✔ bugs 5 and 7: ADD throws a TypeError and the total reads ₹0189; fixed: no error, ₹189 then ₹238, badge counts
  ✔ bug 6: the offer request is a 404; fixed: 200 and the offer shows
  ✔ console snippets: find-overflow names the promo banner (and nothing once fixed); outline-all toggles
  ✔ console snippet: log-focus reports each Tab stop in order

    # Bug Tool that found it Lesson
    1 Sideways scroll Device toolbar + snippet Fixed widths break small screens: use max-width

    3 One column grid badge + Styles warning Typos in CSS fail silently
    4 Badges in the corner Computed position absolute needs a positioned ancestor
    5 TypeError Console → Sources null = your selector found nothing
    6 Offer missing Network Check the status and URL of every request
    7 ₹0189 Breakpoint + Watch Data from the DOM is text: convert with Number()
