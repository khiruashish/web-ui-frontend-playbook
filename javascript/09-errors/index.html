    9. Errors, Debugging & Good Habits¶

    Beginner Intermediate

    Every developer writes bugs every day. What makes you fast is reading the error, finding the line, and checking your assumptions with the console and DevTools. This lesson also covers modules (splitting code into files) and the habits that keep code readable.

    Reading an error message¶

    const cart = undefined;
console.log("Before the crash");
console.log(cart.items);           // TypeError: reading a property of undefined
console.log("This line never runs");
    Console output
    Before the crash
Uncaught TypeError: Cannot read properties of undefined (reading 'items')

    In the browser, an uncaught error looks like this:

    Uncaught TypeError: Cannot read properties of undefined (reading 'items')
    at app.js:3:18
    Part Meaning
    Uncaught Nothing caught it with try/catch, so the script stopped. Nothing after this line ran.
    TypeError The kind of error (see the table below).
    Cannot read properties of undefined (reading 'items') What went wrong: you wrote something.items, and something was undefined.
    app.js:3:18 Where: file, line 3, column 18. Click it in DevTools to jump to the exact spot.

    Read the message, then go to the line. Most bugs are explained right there.

    The errors you'll see most¶

    const examples = [
  () => totl + 1,                                // a typo in a variable name
  () => { const a = 1; a = 2; },                 // reassigning a const
  () => null.length,                             // a property of null
  () => "apple".toUppercase(),                   // a method that doesn't exist (case matters)
  () => JSON.parse("{name: 'Apple'}"),           // JSON needs double quotes around keys and strings
];
for (const run of examples) {
  try {
    run();
  } catch (err) {
    console.log(`${err.name}: ${err.message}`);
  }
}
    Console output
    ReferenceError: totl is not defined
TypeError: Assignment to constant variable.
TypeError: Cannot read properties of null (reading 'length')
TypeError: "apple".toUppercase is not a function
SyntaxError: Expected property name or '}' in JSON at position 1 (line 1 column 2)
    Error Usual cause Fix
    ReferenceError: totl is not defined A typo, or a variable used outside its scope Check the spelling and where it was declared
    TypeError: Assignment to constant variable Reassigning a const Use let if it really changes
    TypeError: Cannot read properties of null querySelector found nothing, or data was missing Check the selector; use ?. for optional data
    TypeError: … is not a function A typo in a method name (case matters), or the value isn't what you think console.log the value and its typeof
    SyntaxError: … in JSON Invalid JSON (single quotes, trailing commas, an HTML error page instead of JSON) Check response.ok and the raw text

    Throwing your own errors¶

    function setQuantity(qty) {
  if (!Number.isInteger(qty) || qty < 0) {
    throw new RangeError(`Quantity must be a whole number ≥ 0, got ${qty}`);
  }
  return qty;
}

for (const value of [2, -1, 1.5]) {
  try {
    console.log("OK:", setQuantity(value));
  } catch (err) {
    console.log(`${err.name}: ${err.message}`);
  }
}
    Console output
    OK: 2
RangeError: Quantity must be a whole number ≥ 0, got -1
RangeError: Quantity must be a whole number ≥ 0, got 1.5
    Code What it does
    Number.isInteger(qty) true only for whole numbers.
    throw new RangeError(…) Stops the function and hands the error to the nearest catch. RangeError (value out of range) and TypeError (wrong type) are good built-in choices; Error for everything else.
    try { … } catch (err) { … } Catches it, so the loop carries on with the next value.

    Throw early with a clear message ("Quantity must be a whole number ≥ 0, got -1") instead of letting bad data cause a confusing error three functions later.

    Console tricks¶

    const product = { id: "apple", pricePaise: 18900 };
console.log("plain log", product);
console.info("info: same as log, different icon in the browser");
console.warn("warn: yellow in the browser");
console.error("error: red in the browser, with a stack trace");
console.log({ product });           // wrap in { } to print the variable's NAME too
    Console output
    plain log { id: 'apple', pricePaise: 18900 }
info: same as log, different icon in the browser
warn: yellow in the browser
error: red in the browser, with a stack trace
{ product: { id: 'apple', pricePaise: 18900 } }

    In the browser, warn shows yellow, error shows red with a stack trace, and the console's filter buttons show one level at a time. console.log({ product }) prints the name of the variable along with its value. Also handy: console.table(array) draws an array of objects as a table.

    Debugging in DevTools (step by step)¶

    console.log is fine for quick checks. For anything harder, pause the code and look around:

    1. Open DevTools (F12) → Sources (Chrome/Edge) or Debugger (Firefox).
    2. Open your .js file (Ctrl+P / Cmd+P and type its name).
    3. Click a line number to set a breakpoint (a blue marker).
    4. Do the thing that runs that code (click ADD). The page freezes on that line.
    5. Hover over any variable to see its value, or read them all in the Scope panel.
    6. Step through: F10 next line · F11 into a function · F8 continue.
    7. Add debugger; to your code to pause there whenever DevTools is open.

    For the full tour (Styles, Computed, Grid overlays, every kind of breakpoint, Network status codes) and a page of planted bugs to practise on, see Debugging with DevTools and the Bug Lab.

    Other DevTools panels you'll use daily: Elements (see and edit the live DOM and CSS), Network (every request, its status and its response: the first place to look when fetch fails), Application (localStorage, cookies).

    Modules: splitting code into files¶

    Once a script grows past a couple of hundred lines, split it. Modules let each file export what others may use and import what it needs.

    js/money.js
    export const FREE_DELIVERY_FROM = 19900;

export function formatPaise(paise) {
  return new Intl.NumberFormat("en-IN", { style: "currency", currency: "INR" }).format(paise / 100);
}
    js/cart.js
    import { formatPaise, FREE_DELIVERY_FROM } from "./money.js";

const cart = new Map();

export function addToCart(id, pricePaise) {
  const line = cart.get(id) ?? { qty: 0, pricePaise };
  cart.set(id, { ...line, qty: line.qty + 1 });
}

export function total() {
  let paise = 0;
  for (const line of cart.values()) paise += line.qty * line.pricePaise;
  return formatPaise(paise);
}
    index.html
    <script type="module" src="js/app.js"></script>
    js/app.js
    import { addToCart, total } from "./cart.js";

addToCart("apple", 18900);
console.log(total());   // ₹189.00
    Code What it does
    export function … / export const … Makes it available to other files. Anything not exported stays private to the file (like cart above).
    import { a, b } from "./money.js"; Brings in named exports. The path is relative and needs the .js extension in the browser.
    <script type="module"> Required for import/export in the browser. Modules are deferred automatically and run in strict mode.

    Like fetch, modules don't load from file://: use Live Server or python3 -m http.server. Angular, React and Vite projects use exactly this syntax; the build tool bundles the files for you.

    Habits that make code easy to read¶

    // 1. const by default, let only when the value changes, never var
// 2. === not ==
// 3. Name things for what they ARE: cartTotalPaise, not x or data2
// 4. Small functions that do one thing
// 5. Return early instead of nesting if inside if

// Nested (hard to read)
function canCheckout1(cart, user) {
  if (cart.length > 0) {
    if (user) {
      if (user.address) {
        return true;
      }
    }
  }
  return false;
}

// Early returns (easy to read)
function canCheckout2(cart, user) {
  if (cart.length === 0) return false;
  if (!user) return false;
  return Boolean(user.address);
}

const user = { name: "Asha", address: "21 MG Road" };
console.log(canCheckout1(["apple"], user), canCheckout2(["apple"], user));
console.log(canCheckout1([], user), canCheckout2([], user));
    Console output
    true true
false false

    Both functions give the same answers, but canCheckout2 is far easier to read and change. The checklist:

    • const by default, let when it changes, never var.
    • ===, never ==.
    • Names say what the value is: cartTotalPaise, isLoggedIn, renderProduct().
    • Small functions that do one thing; return early instead of nesting.
    • Keep data (state) separate from the DOM; change the state, then render.
    • Use textContent for data, never innerHTML.
    • Handle the failure path of every await.
    • Use a formatter (Prettier) and a linter (ESLint) so style is never a discussion.

    Try it¶

    1. Open the store demo, set a breakpoint inside setQty in store.js, click ADD and step through render(). Watch count and subtotal change in the Scope panel.
    2. Break something on purpose (misspell a variable), read the error, click the file link, and fix it.
    3. Split lesson 5's cart-bill example into money.js, cart.js and app.js modules.

    Solutions¶

    Try each exercise yourself first, then open its solution to compare.

    1. Step through the store with a breakpoint

    What you should see, in order:

    1. Click ADD on Shimla Apple: the page freezes on your breakpoint in setQty. The Scope panel shows card (the <article>), and qty = 1.
    2. F10 over the const { id, name, price } = card.dataset; line: id = "apple", name = "Shimla Apple", and price = "18900", a string (data attributes always are).
    3. Step into render() with F11. In the for…of loop, watch count go 0 → 1 and subtotal 0 → 18900.
    4. F8 to continue: the card shows the − 1 + stepper and the badge shows 1.
    2. Read and fix an error

    For example, change cart.set(id, …) to crat.set(id, …) in store.js and click ADD. Chrome's console shows (captured from a real run; the file paths are shortened):

    Uncaught ReferenceError: crat is not defined
    at setQty (store.js:25:7)
    at <anonymous> (store.js:40:48)

    The first line names the problem: a variable that doesn't exist. The at … lines are the stack trace, newest call first: the error happened inside setQty, which was called from the anonymous click listener on line 40. Click the store.js link to jump to the code (Chrome points at the start of the if/else statement that contains the typo), fix it, and reload.

    3. Split the cart bill into modules

    Three files, each with one job. money.js knows about paise and currencies:

    money.js
    // money.js: everything about prices. No other file needs to know about paise or currency formats.
export const FREE_DELIVERY_FROM = 19900; // ₹199
export const DELIVERY_FEE = 2500;        // ₹25

export function rupees(paise) {
  return `₹${(paise / 100).toFixed(2)}`;
}

export function deliveryFee(subtotalPaise) {
  return subtotalPaise >= FREE_DELIVERY_FROM ? 0 : DELIVERY_FEE;
}

    cart.js builds the bill and imports only what it needs:

    cart.js
    // cart.js: turns a catalogue + a cart into bill lines. It imports only what it needs from money.js.
import { deliveryFee } from "./money.js";

export function billFor(catalogue, cart) {
  const lines = cart.map(({ id, qty }) => {
    const { name, pricePaise } = catalogue.get(id);
    return { name, qty, linePaise: pricePaise * qty };
  });
  const subtotal = lines.reduce((sum, line) => sum + line.linePaise, 0);
  const delivery = deliveryFee(subtotal);
  return { lines, delivery, total: subtotal + delivery };
}

    app.js is the entry point that wires them together:

    app.js
    // app.js: the entry point. Load it with <script type="module" src="app.js"></script>, or run `node app.js`.
import { rupees } from "./money.js";
import { billFor } from "./cart.js";

const catalogue = new Map([
  ["apple", { name: "Shimla Apple", pricePaise: 18900 }],
  ["milk", { name: "Full Cream Milk", pricePaise: 6800 }],
  ["bread", { name: "Whole Wheat Bread", pricePaise: 5000 }],
]);
const cart = [
  { id: "apple", qty: 2 },
  { id: "bread", qty: 1 },
];

const { lines, delivery, total } = billFor(catalogue, cart);
for (const line of lines) console.log(`${line.name.padEnd(18)} × ${line.qty}  ${rupees(line.linePaise)}`);
console.log(`Delivery: ${delivery ? rupees(delivery) : "FREE"}`);
console.log(`To pay:   ${rupees(total)}`);
    Console output
    Shimla Apple       × 2  ₹378.00
Whole Wheat Bread  × 1  ₹50.00
Delivery: FREE
To pay:   ₹428.00

    Exactly the same bill as lesson 5, but now rupees() and deliveryFee() can be reused by any other file, and cart.js can be tested without a page. This output comes from running node app.js (Node 22 understands import/export directly).

    Common mistakes¶

    • Ignoring the red error and changing random things. Read the message and go to the line first.
    • Leaving console.log and debugger lines in finished code.
    • Catching errors and doing nothing (catch (err) {}): the bug is still there, now silent.
    • Forgetting type="module", then getting Cannot use import statement outside a module.
