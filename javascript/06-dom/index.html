    6. The DOM: Changing the Page¶

    Beginner Intermediate

    When the browser reads your HTML, it builds a tree of objects called the DOM (Document Object Model). Each tag becomes an object you can find, read and change from JavaScript. Change the DOM and the browser redraws the page.

    flowchart TD doc["document"] --> html["html"] html --> head["head"] html --> body["body"] body --> h1["h1#title<br/>'Today's products'"] body --> p["p.subtitle"] body --> div["div.controls"] div --> b1["button#rename"] div --> b2["button#highlight"] div --> b3["button#add"] body --> ul["ul#product-list"] ul --> li1["li (made by JS)"] ul --> li2["li (made by JS)"]

    What you see¶

    Click the three buttons. Open it full-size: 06-dom.html, then press F12 and look at the Elements panel: the <li>s aren't in the HTML file; JavaScript created them.

    The HTML¶

    <h1 id="title">Today's products</h1>
<p class="subtitle">Loaded from a JavaScript array.</p>

<div class="controls">
  <button type="button" id="rename">Change the heading</button>
  <button type="button" id="highlight">Highlight cheap items</button>
  <button type="button" id="add">Add a product</button>
</div>

<ul id="product-list"></ul>

    The list <ul id="product-list"> is empty. JavaScript fills it from an array: the same way a real store fills its pages from data sent by the server.

    1. Find elements¶

    // 1. Find elements
const title = document.querySelector("#title");          // first match for a CSS selector
const list = document.querySelector("#product-list");
const buttons = document.querySelectorAll(".controls button");   // ALL matches (a NodeList)
console.log(buttons.length);                               // 3
    Code What it does
    document The whole page. The starting point for everything.
    document.querySelector("#title") Finds the first element matching a CSS selector (#id, .class, tag, [data-x], nav a…). Gives null if nothing matches.
    document.querySelectorAll(".controls button") Finds all matches, as a NodeList. You can loop over it with for…of; use [...list] for array methods like map.
    buttons.length How many were found: 3.

    You can also search inside an element: list.querySelectorAll("li") only looks within the list.

    2. Build elements from data¶

    // 2. Build elements from data
const products = [
  { name: "Shimla Apple", pricePaise: 18900 },
  { name: "Robusta Banana", pricePaise: 4900 },
  { name: "Full Cream Milk", pricePaise: 6800 },
];

function renderProduct(product) {
  const li = document.createElement("li");                 // a new, empty <li> (not on the page yet)
  li.dataset.price = product.pricePaise;                   // sets data-price="18900"

  const name = document.createElement("span");
  name.textContent = product.name;                         // textContent: safe, never runs HTML

  const price = document.createElement("span");
  price.className = "price";
  price.textContent = `₹${product.pricePaise / 100}`;

  li.append(name, price);                                  // put the spans inside the <li>
  return li;
}

list.append(...products.map(renderProduct));               // put every <li> on the page in one go
    Code What it does
    const products = [ … ]; The data, as an array of objects (lesson 4).
    function renderProduct(product) A small function: one product in, one <li> out. Reusable for the first render and for adding later.
    document.createElement("li") Makes a new, empty <li>. It isn't on the page until you insert it.
    li.dataset.price = product.pricePaise; Sets data-price="18900". dataset.someName ↔ data-some-name.
    name.textContent = product.name; Sets the text. textContent treats everything as plain text, so data can never inject HTML.
    price.className = "price"; Sets the class attribute (for the CSS rule .price { font-weight: 700 }).
    li.append(name, price); Puts both spans inside the <li>, in order.
    list.append(...products.map(renderProduct)); map turns 3 products into 3 <li>s; spread passes them all to append in one go. One DOM update is faster than three.

    innerHTML with data is a security hole

    li.innerHTML = product.name would run any HTML inside the name. If a name ever came from a user or a server, someone could insert <img src=x onerror="stealCookies()">. This is called XSS (cross-site scripting). Use textContent for data, and keep innerHTML for fixed markup you wrote yourself.

    3. Change what's on the page¶

    // 3. Change what's on the page
document.querySelector("#rename").addEventListener("click", () => {
  title.textContent = "Fresh picks for you";               // change text
  title.style.color = "#0c831f";                           // change one style (prefer classes)
});

document.querySelector("#highlight").addEventListener("click", () => {
  for (const li of list.querySelectorAll("li")) {
    const cheap = Number(li.dataset.price) < 10000;
    li.classList.toggle("highlight", cheap);               // add the class if cheap, remove it if not
  }
});

document.querySelector("#add").addEventListener("click", (event) => {
  list.prepend(renderProduct({ name: "Brown Eggs", pricePaise: 8400 }));   // add at the top
  event.currentTarget.disabled = true;                     // the button that was clicked
  event.currentTarget.textContent = "Added";
});
    Code What it does
    addEventListener("click", () => { … }) Run this function when the button is clicked (lesson 7 covers events).
    title.textContent = "Fresh picks for you"; Replaces the heading's text.
    title.style.color = "#0c831f"; Sets one inline style. Fine for one-offs; for anything bigger, toggle a class and keep the styling in CSS.
    list.querySelectorAll("li") Only the <li>s inside the list.
    Number(li.dataset.price) < 10000 Data attributes are strings; convert before comparing (lesson 1).
    li.classList.toggle("highlight", cheap) Adds the class when cheap is true, removes it when false. Also: classList.add(), .remove(), .contains().
    list.prepend(…) Inserts at the start of the list (append = end; before/after = next to an element).
    event.currentTarget The element the listener is attached to: here, the clicked button.
    .disabled = true Many attributes have matching properties: disabled, hidden, value, checked, href. For any other attribute use setAttribute("aria-label", "…") / getAttribute(…).

    Cheat sheet¶

    Task Code
    Find one / all document.querySelector(sel) / document.querySelectorAll(sel)
    Nearest ancestor matching el.closest(".product-card")
    Read / change text el.textContent
    Read an input input.value (always a string)
    Classes el.classList.add / remove / toggle / contains("name")
    Attributes el.getAttribute("x"), el.setAttribute("x", "y"), el.removeAttribute("x")
    Data attributes el.dataset.productId ↔ data-product-id
    Show / hide el.hidden = true / false
    Create document.createElement("li")
    Insert parent.append(child), parent.prepend(child), el.before(x), el.after(x)
    Replace all children parent.replaceChildren(...newChildren)
    Remove el.remove()

    Try it¶

    1. Add a fourth button "Sort by price" that re-appends the <li>s in price order (hint: [...list.children], toSorted, list.append(...)).
    2. Give each <li> a "×" button that removes it.
    3. Show the total of all prices in a <p> under the list, and update it when a product is added.

    Solutions¶

    Try each exercise yourself first, then open its solution to compare.

    All three solutions together, live (the code below is included from this file):

    1. Sort by price 
    <button type="button" id="sort">Sort by price</button>

    // Exercise 1: re-append the <li>s in price order. append() MOVES existing elements, so nothing is re-created.
document.querySelector("#sort").addEventListener("click", () => {
  const rows = [...list.children].toSorted((a, b) => Number(a.dataset.price) - Number(b.dataset.price));
  list.append(...rows);
});

    list.children is a live HTMLCollection (no array methods), so spread it first. append() moves elements that are already on the page; nothing is copied or re-created.

    2. A × button on every row

    Build the button inside renderProduct, so every row, including ones added later, gets one:

    const remove = document.createElement("button");         // Exercise 2: a × button in every row
remove.type = "button";
remove.className = "remove";
remove.textContent = "×";
remove.setAttribute("aria-label", `Remove ${product.name}`);

li.append(name, price, remove);

    Then one listener on the list removes the right row (event delegation, lesson 7):

    // Exercise 2: one listener on the list removes whichever row's × was clicked (event delegation, lesson 7)
list.addEventListener("click", (event) => {
  const button = event.target.closest(".remove");
  if (!button) return;
  button.closest("li").remove();
  updateTotal();
});
    3. A total that stays in sync 
    <p id="total"></p>

    // Exercise 3: the total of every price on the list, recalculated from the DOM whenever it changes
const totalText = document.querySelector("#total");
function updateTotal() {
  const prices = [...list.querySelectorAll("li")].map((li) => Number(li.dataset.price));
  const totalPaise = prices.reduce((sum, p) => sum + p, 0);
  totalText.textContent = `Total: ₹${totalPaise / 100}`;
}
updateTotal();

    Then call updateTotal() after every change: adding a product and removing one. Forgetting one of those calls is exactly the kind of bug that the "change state, then render everything" pattern (used by the FreshCart cart) avoids.

    Common mistakes¶

    • Running the script before the HTML exists, so querySelector returns null. Use <script defer> or put the script at the end of <body>.
    • querySelector("product-list") without # or .: that searches for a <product-list> tag.
    • Calling .forEach or .map on something that isn't an array. querySelectorAll has forEach but not map: spread it first.
    • Building HTML strings with data and innerHTML (XSS).
