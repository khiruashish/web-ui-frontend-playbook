    8. Async: Timers, Promises & fetch¶

    Intermediate

    Some things take time: loading products from a server, waiting for payment, a timer. JavaScript doesn't stop and wait; it carries on and runs your code later, when the result is ready. This is called asynchronous code.

    JavaScript doesn't wait¶

    console.log("1. Order button clicked");
setTimeout(() => console.log("3. Payment confirmed (after 200 ms)"), 200);
setTimeout(() => console.log("2. Packing started (after 100 ms)"), 100);
console.log("0. JavaScript doesn't wait: this line runs straight away");
    Console output
    1. Order button clicked
0. JavaScript doesn't wait: this line runs straight away
2. Packing started (after 100 ms)
3. Payment confirmed (after 200 ms)
    Code What it does
    setTimeout(fn, 200) "Call fn in about 200 ms." It schedules and returns immediately.
    The printed order 1, then 0 (the next line runs at once), then 2 after 100 ms, then 3 after 200 ms. The order you write isn't the order things happen.

    The browser has a single main thread. If JavaScript waited for every network request, the page would freeze. Instead, slow work happens in the background and your function is queued to run when it's done.

    Promises¶

    // A Promise is a value that will arrive later: it ends up "fulfilled" (a result) or "rejected" (an error)
function checkStock(productId) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (productId === "apple") resolve({ productId, available: 12 });
      else reject(new Error(`Unknown product: ${productId}`));
    }, 50);
  });
}

checkStock("apple")
  .then((result) => console.log("In stock:", result.available))
  .catch((err) => console.log("Failed:", err.message));

checkStock("dragonfruit")
  .then((result) => console.log("In stock:", result.available))
  .catch((err) => console.log("Failed:", err.message));
    Console output
    In stock: 12
Failed: Unknown product: dragonfruit
    Code What it does
    new Promise((resolve, reject) => { … }) A promise is an object for a value that will arrive later. You get it straight away; the value comes later.
    resolve(value) "It worked, here's the result." The promise becomes fulfilled.
    reject(new Error(…)) "It failed." The promise becomes rejected.
    .then((result) => …) Runs when it's fulfilled.
    .catch((err) => …) Runs when it's rejected. Always handle failures.

    You'll rarely write new Promise yourself. fetch() and most browser APIs return promises; your job is to use them.

    async / await: async code that reads top to bottom¶

    const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function placeOrder() {
  console.log("Placing order…");
  await wait(50);                       // pause THIS function until the promise settles
  console.log("Payment done");
  await wait(50);
  console.log("Order confirmed");
  return 1042;                          // an async function always returns a promise
}

const orderId = await placeOrder();     // await works at the top level of modules and the console
console.log("Order id:", orderId);
    Console output
    Placing order…
Payment done
Order confirmed
Order id: 1042
    Code What it does
    async function placeOrder() Marks the function as asynchronous. It always returns a promise.
    await wait(50); Pauses this function until the promise settles, then continues. The rest of the page keeps working meanwhile.
    return 1042; The promise returned by placeOrder() resolves to 1042.
    const orderId = await placeOrder(); Wait for the result. await is allowed inside async functions, in <script type="module"> and in the console.

    async/await is the same promises as .then(), written so it reads like normal step-by-step code.

    Handling errors: try / catch / finally¶

    async function fetchPrice(productId) {
  await new Promise((r) => setTimeout(r, 20));
  if (productId !== "milk") throw new Error("Price service is down");
  return 6800;
}

async function showPrice(productId) {
  try {
    const price = await fetchPrice(productId);
    console.log(`${productId}: ₹${price / 100}`);
  } catch (err) {
    console.log(`Could not load ${productId}: ${err.message}`);   // show a friendly message, keep the app running
  } finally {
    console.log("(hide the loading spinner)");                    // runs whether it worked or not
  }
}

await showPrice("milk");
await showPrice("bread");
    Console output
    milk: ₹68
(hide the loading spinner)
Could not load bread: Price service is down
(hide the loading spinner)
    Code What it does
    throw new Error("Price service is down") Inside an async function, throw rejects its promise.
    try { … } Run this code…
    catch (err) { … } …and if anything inside try throws (or an awaited promise rejects), jump here instead of crashing. err.message is the text.
    finally { … } Runs either way: the place to hide a loading spinner or re-enable a button.

    Doing things at the same time¶

    const fakeApi = (name, ms) => new Promise((resolve) => setTimeout(() => resolve(name), ms));

let start = Date.now();
const a = await fakeApi("products", 100);
const b = await fakeApi("offers", 100);
const about = (ms) => (ms >= 150 ? "about 200 ms" : "about 100 ms");
console.log("one after another:", a, b, about(Date.now() - start));

start = Date.now();
const [c, d] = await Promise.all([fakeApi("products", 100), fakeApi("offers", 100)]);
console.log("at the same time: ", c, d, about(Date.now() - start));
    Console output
    one after another: products offers about 200 ms
at the same time:  products offers about 100 ms
    Code What it does
    await a; await b; One after another: the second request doesn't start until the first has finished. 100 + 100 ms.
    await Promise.all([a, b]) Both start immediately; wait until all are done. About 100 ms total. Results come back in the same order as the array.

    If one promise in Promise.all rejects, the whole thing rejects. Use Promise.allSettled when you want every result, even failures. (Build both yourself in Coding Interview #10.)

    fetch: loading data from a server¶

    // What fetch() code looks like. Here fetch is faked so the example runs anywhere;
// the live demo on this page calls the real fetch().
const fetch = async (url) => ({
  ok: url.endsWith("products.json"),
  status: url.endsWith("products.json") ? 200 : 404,
  json: async () => [{ name: "Shimla Apple", pricePaise: 18900 }],
});

async function loadProducts(url) {
  const response = await fetch(url);
  if (!response.ok) throw new Error(`HTTP ${response.status}`);   // fetch does NOT reject on 404/500
  return response.json();
}

console.log(await loadProducts("/api/products.json"));
try {
  await loadProducts("/api/missing.json");
} catch (err) {
  console.log("Error:", err.message);
}
    Console output
    [ { name: 'Shimla Apple', pricePaise: 18900 } ]
Error: HTTP 404
    Code What it does
    const response = await fetch(url); Sends an HTTP request and waits for the headers of the response.
    if (!response.ok) throw … Important: fetch only rejects on network failure (offline, DNS). A 404 or 500 is still a "successful" response, so check response.ok (status 200–299) yourself.
    return response.json(); Reads the body and parses it from JSON into objects. This is also a promise.

    Live demo: loading, success and error states¶

    This demo really calls fetch("products.json"), a file next to it. Click both buttons. Open it full-size: 08-fetch.html.

    <div class="controls">
  <button type="button" id="load">Load products</button>
  <button type="button" class="secondary" id="broken">Load from a broken URL</button>
</div>
<p id="status" role="status"></p>
<ul id="grid"></ul>

    const statusText = document.querySelector("#status");
const grid = document.querySelector("#grid");
const buttons = document.querySelectorAll(".controls button");
const wait = (ms) => new Promise((resolve) => setTimeout(resolve, ms));

async function loadProducts(url) {
  const response = await fetch(url);
  if (!response.ok) throw new Error(`The server answered ${response.status}`);
  return response.json();                                  // parse the JSON body (also async)
}

function showLoading(isLoading) {
  for (const button of buttons) button.disabled = isLoading;
  if (isLoading) {
    statusText.className = "";
    statusText.textContent = "Loading…";
    grid.replaceChildren();                                // clear old results
  }
}

async function show(url) {
  showLoading(true);
  try {
    await wait(400);                                       // pretend the network is slow, so you can see "Loading…"
    const products = await loadProducts(url);
    grid.replaceChildren(
      ...products.map((p) => {
        const li = document.createElement("li");
        li.innerHTML = "<span></span><strong></strong><div></div>";
        li.querySelector("span").textContent = p.emoji;
        li.querySelector("strong").textContent = p.name;
        li.querySelector("div").textContent = `₹${p.pricePaise / 100}`;
        return li;
      }),
    );
    statusText.textContent = `${products.length} products loaded.`;
  } catch (err) {
    statusText.className = "error";
    statusText.textContent = `Sorry, we couldn't load products (${err.message}). Please try again.`;
  } finally {
    showLoading(false);
  }
}

document.querySelector("#load").addEventListener("click", () => show("products.json"));
document.querySelector("#broken").addEventListener("click", () => show("no-such-file.json"));
    Code What it does
    <script type="module"> A module script: deferred automatically, strict mode, and allowed to use import and top-level await.
    <p id="status" role="status"> A live region: screen readers announce "Loading…", "4 products loaded." and the error.
    function showLoading(isLoading) One function for the loading state: disables both buttons (no double-clicks), shows "Loading…" and clears old results.
    await wait(400); Fake slowness, only so you can see the loading state. Remove it in real code.
    const products = await loadProducts(url); Fetch and parse. If anything fails, we jump to catch.
    grid.replaceChildren(...products.map(…)) Build one <li> per product (lesson 6) and swap them in.
    li.innerHTML = "<span></span>…" then textContent Fixed markup via innerHTML; the data goes in through textContent (safe from XSS).
    catch (err) { … } Show a friendly message. Never leave the user staring at "Loading…" forever.
    finally { showLoading(false); } Re-enable the buttons whether it worked or not.

    Every data-loading UI needs these three states: loading, success and error (and often a fourth: empty).

    Why not open this file by double-clicking?

    Browsers block fetch() from pages opened as file://. Use VS Code's Live Server, or run python3 -m http.server in the folder and open http://localhost:8000/08-fetch.html.

    Try it¶

    1. Add a "Retry" button to the error message that calls show("products.json") again.
    2. Show "No products found" when the JSON is an empty array [].
    3. Load products.json and a second file (e.g. offers.json) at the same time with Promise.all.

    Solutions¶

    Try each exercise yourself first, then open its solution to compare.

    All three solutions together, live (a third button loads an empty list):

    1. A Retry button 
    // Exercise 1: the error message gets a Retry button that loads the good URL
statusText.className = "error";
statusText.textContent = `Sorry, we couldn't load products (${err.message}). `;
const retry = document.createElement("button");
retry.type = "button";
retry.className = "secondary";
retry.textContent = "Retry";
retry.addEventListener("click", () => show("products.json"));
statusText.append(retry);

    The button is created with createElement, not innerHTML, so the error text (err.message) never gets parsed as HTML.

    2. “No products found” 
    // Exercise 2: an empty list is a success, but it needs its own message
if (products.length === 0) {
  statusText.textContent = "No products found.";
  return;                                              // finally still runs
}

    An empty array is a successful response, so it's not an error, but it still needs its own message. return inside try still runs finally, so the buttons are re-enabled.

    3. Two files at once with Promise.all 
    // Exercise 3: both files at the same time; total wait ≈ the slower one, not the sum
const [products, offers] = await Promise.all([loadProducts(url), loadProducts("offers.json")]);
document.querySelector("#offers").textContent = offers.map((o) => o.title).join(" · ");

    Both requests start immediately, and the destructuring [products, offers] matches the order of the array, not the order the responses arrive in. If either request fails, Promise.all rejects and the catch shows the error. (See the offers file.)

    Common mistakes¶

    • Forgetting await: you get a Promise object instead of the data (console.log shows Promise {<pending>}).
    • Not checking response.ok, then trying to parse an HTML 404 page as JSON.
    • No try/catch around await: one failed request breaks the whole feature, silently.
    • Awaiting independent requests one by one when Promise.all could run them together.
    • Using await inside forEach (it doesn't wait). Use for…of or Promise.all(array.map(…)).
