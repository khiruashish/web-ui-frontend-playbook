01 Centering

Beginner

What you see: A box sitting dead-centre, horizontally and vertically, inside a larger area.

Perfectly centred
Show the HTML & CSS

HTML

<div class="center-demo">
  <div class="tile">Perfectly centred</div>
</div>

CSS

.center-demo {
  display: grid;
  place-items: center;
  min-height: 220px;
}

Why this works

  • display: grid turns the container into a one-cell grid.
  • place-items: center centres the item on both axes inside that cell.
  • Flexbox equivalent: display:flex; justify-content:center; align-items:center.

  <div class="tile holy__main">Main content</div>
  <aside class="tile">Aside</aside>
  <footer class="tile">Footer</footer>

CSS

.holy {
  display: grid;
  gap: var(--gap);
  grid-template-areas: "header" "nav" "main" "aside" "footer";
}
.holy > header { grid-area: header; }
.holy > nav    { grid-area: nav; }
.holy > .holy__main { grid-area: main; min-height: 160px; }
.holy > aside  { grid-area: aside; }
.holy > footer { grid-area: footer; }

@media (width >= 48em) {
  .holy {
    grid-template-columns: 160px 1fr 160px;
    grid-template-areas:
      "header header header"
      "nav    main   aside"
      "footer footer footer";
  }
}

Why this works

  • Mobile-first: the base CSS is a single column in reading order.
  • grid-template-areas draws the desktop layout as text. Changing the layout means redrawing the map, not moving HTML.
  • Semantic elements (header, nav, aside, footer) describe each region. On a real page the middle area is your one <main>; it's a div here only because this demo already sits inside the page's main.

03 Sidebar that wraps (no media query)

Intermediate

What you see: A narrow sidebar next to wide content. When there's not enough room, the sidebar drops above the content on its own.

Sidebar (ideal 220px)
Content: takes all remaining space, and wraps below the sidebar when it would get narrower than 55% of the row.
Show the HTML & CSS

HTML

<div class="with-sidebar">
  <aside class="tile">Sidebar (ideal 220px)</aside>
  <div class="tile">Content: takes all remaining space, and wraps below the sidebar when it would get narrower than 55% of the row.</div>
</div>

CSS

.with-sidebar {
  display: flex;
  flex-wrap: wrap;
  gap: var(--gap);
}
.with-sidebar > :first-child { flex: 1 1 220px; }
.with-sidebar > :last-child  { flex: 999 1 0; min-inline-size: 55%; }

Why this works

  • The content's huge flex-grow (999) means it takes almost all the spare space, so the sidebar stays near 220px.
  • min-inline-size: 55% on the content forces a wrap once the row is too narrow for both.
  • This is an intrinsic layout: it responds to its container, not the viewport, so it works in any slot.

04 Pancake stack & sticky footer

Beginner

What you see: Header, content, footer stacked vertically. The footer stays at the very bottom even when there's little content.

Show the HTML & CSS

HTML

  <header class="tile">Header</header>
  <div class="tile">Main grows to fill the space</div>
  <footer class="tile">Footer stays at the bottom</footer>
</div>

CSS

.pancake {
  display: grid;
  grid-template-rows: auto 1fr auto;
  gap: var(--gap);

HTML

<div class="card-grid">
  <article class="card"><div class="card__img"></div><h3>Mangoes</h3><p>Sweet Alphonso, 1 kg.</p></article>
  <article class="card"><div class="card__img"></div><h3>Bananas</h3><p>Robusta, 1 dozen.</p></article>
  <article class="card"><div class="card__img"></div><h3>Spinach</h3><p>Fresh bunch, 250 g.</p></article>
  <article class="card"><div class="card__img"></div><h3>Tomatoes</h3><p>Farm fresh, 500 g.</p></article>
  <article class="card"><div class="card__img"></div><h3>Milk</h3><p>Toned, 1 litre.</p></article>
</div>

CSS

.card-grid {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(min(180px, 100%), 1fr));
  gap: var(--gap);
}
.card {
  display: grid; gap: .4rem; padding: .8rem;
  background: var(--surface); border: 1px solid var(--border); border-radius: var(--radius);
}
.card h3, .card p { margin: 0; }
.card__img { aspect-ratio: 4 / 3; border-radius: calc(var(--radius) - 4px); background: var(--grad); }

Why this works

  • Repeat, Auto-fit, Minmax: "as many columns as fit, each at least 180px, stretched to fill".
  • min(180px, 100%) stops overflow on screens narrower than 180px.
  • No media queries: the number of columns follows the available width.

HTML

<div class="row12">
  <div class="tile span-12">12</div>
  <div class="tile span-8">8</div><div class="tile span-4">4</div>
  <div class="tile span-6">6</div><div class="tile span-6">6</div>
  <div class="tile span-3">3</div><div class="tile span-3">3</div><div class="tile span-3">3</div><div class="tile span-3">3</div>

CSS

.row12 {
  display: grid;
  grid-template-columns: repeat(12, minmax(0, 1fr));
  gap: var(--gap);
}
.row12 > * { grid-column: 1 / -1; }     /* mobile: full width */
@media (width >= 40em) {
  .span-12 { grid-column: span 12; }
  .span-8  { grid-column: span 8; }
  .span-6  { grid-column: span 6; }
  .span-4  { grid-column: span 4; }
  .span-3  { grid-column: span 3; }
}

Why this works

  • 12 divides evenly by 2, 3, 4 and 6, so it supports halves, thirds and quarters.
  • minmax(0, 1fr) instead of 1fr stops long content from making one column wider than the others.
  • 1 / -1 means "from the first line to the last": full width.

07 Bento grid

Intermediate

What you see: Feature tiles of mixed sizes, one big, some wide, some tall, packed tightly with rounded corners.

Show the HTML & CSS

HTML

<div class="bento">
  <div class="tile big">Big feature</div>
  <div class="tile tall">Tall</div>
  <div class="tile">Small</div>
  <div class="tile">Small</div>
  <div class="tile wide">Wide tile</div>
  <div class="tile">Small</div>
</div>

CSS

.bento {
  display: grid;
  grid-template-columns: repeat(2, 1fr);
  grid-auto-rows: 110px;
  grid-auto-flow: dense;
  gap: var(--gap);
}
.bento .big  { grid-column: span 2; grid-row: span 2; }
.bento .wide { grid-column: span 2; }
.bento .tall { grid-row: span 2; }
.bento > *   { border-radius: 20px; }
@media (width >= 48em) {
  .bento { grid-template-columns: repeat(4, 1fr); }
}

Why this works

  • grid-auto-rows gives every row the same height, so span creates exact 1×1, 2×1, 1×2 and 2×2 tiles.
  • grid-auto-flow: dense fills holes left by big tiles. Be careful: it can change the visual order away from the DOM order.

  <div class="tile" style="height:150px">2</div>
  <div class="tile" style="height:70px">3</div>

  <div class="tile" style="height:80px">7</div>
  <div class="tile" style="height:110px">8</div>
</div>

CSS

.masonry {
  columns: 4 160px;          /* up to 4 columns, each at least 160px */
  column-gap: var(--gap);
}
.masonry > * {
  break-inside: avoid;       /* never split a tile across columns */
  margin-bottom: var(--gap);
}

Why this works

  • CSS multi-column flows items top-to-bottom, then into the next column, which naturally packs uneven heights.
  • Order runs down each column (1, 2 in column one…), not across. Fine for galleries; not for ranked lists.
  • Native masonry for Grid (CSS Grid Lanes) is coming; until it's Baseline this is the zero-JS approach.

15 Full-bleed article

Advanced

What you see: Article text in a narrow readable column, with an image that breaks out to the full width of the page.

Why readable line length matters

Lines of about 45–75 characters are the easiest to read. Longer lines make it hard to find the start of the next line.

Full-bleed image

After the image, the text returns to its comfortable column, with no extra wrapper elements.

Show the HTML & CSS

HTML

<div class="article">
  <h3>Why readable line length matters</h3>
  <p>Lines of about 45–75 characters are the easiest to read. Longer lines make it hard to find the start of the next line.</p>
  <div class="full bleed-img">Full-bleed image</div>
  <p>After the image, the text returns to its comfortable column, with no extra wrapper elements.</p>
</div>

CSS

.article {
  display: grid;
  grid-template-columns:
    [full-start] minmax(1rem, 1fr)
    [content-start] minmax(0, 60ch) [content-end]
    minmax(1rem, 1fr) [full-end];
  row-gap: .8rem;
}
.article > *     { grid-column: content; margin: 0; }
.article > .full { grid-column: full; }
.bleed-img { min-height: 160px; display: grid; place-items: center; background: var(--grad); color: #fff; font-weight: 700; }

Why this works

  • Named grid lines ([content-start], [full-end]) create two "lanes".
  • By default every child sits in the content lane; adding .full moves an element to the full lane.
  • The outer minmax(1rem, 1fr) tracks act as both centring margins and minimum gutters on phones.

  .feature { grid-template-columns: 1fr 1fr; gap: 2rem; }
  .feature:nth-child(even) .feature__img { order: -1; }   /* image first on every other row */
}

Why this works

  • :nth-child(even) selects every second row; order: -1 moves its image before the text visually.
  • The HTML order (text, then image) stays the same, so screen readers and keyboard users always get the text first.

.docs-scroll { max-height: 300px; overflow: auto; border: 1px solid var(--border); border-radius: var(--radius); }

Why this works

  • position: sticky; top: 1rem keeps the TOC in view while its scroll container scrolls.
  • align-self: start is essential: grid items stretch to the row's height by default, which leaves a sticky element no room to stick.
  • On phones the TOC becomes a horizontal wrapping row above the article.
