    Build an E-commerce Page: Start Here¶

    Beginner Intermediate

    In this tab you build FreshCart, a responsive grocery store page (think BigBasket, Blinkit or Instacart), one small component at a time. Every line of code is explained. By the end you have a real page that works on a phone and on a desktop, with a working cart.

    Open it full-size: store.html. Press Ctrl+Shift+M in DevTools to view it as a phone, click ADD on a few products, then open the cart.

    How to start (10 minutes of setup)¶

    You need only a browser and a text editor. No Node, no framework, no build step.

    1. Install an editor. VS Code is free. Add the Live Server extension: it reloads the page every time you save.

    2. Create this folder structure. One CSS file per component keeps every file short and easy to find.

      freshcart/
├── store.html          ← the page (all the HTML)
├── css/
│   ├── base.css        ← colours, spacing, reset, buttons   (lesson 1)
│   ├── header.css      ← announcement bar, header, nav     (lesson 2)
│   ├── home.css        ← hero, offers, category tiles      (lesson 3)
│   ├── product.css     ← product card + product grid       (lesson 4)
│   ├── listing.css     ← filters, sort bar, page layout    (lesson 5)
│   ├── cart.css        ← cart drawer                       (lesson 6)
│   └── footer.css      ← footer + mobile bottom nav        (lesson 7)
└── js/
    └── store.js        ← cart, filters and sort            (lessons 4–6)

    3. Type, don't paste. Typing each line is slower but you'll remember it. Paste only when you're stuck.

    4. Right-click → Open with Live Server on store.html. Keep DevTools open (F12) while you work.
    5. After each lesson, resize the browser from wide to narrow and check nothing overflows sideways.

    Want the finished files?

    Every file in this tab lives in the repository under docs/ecommerce/demos/. Download the folder and open store.html in a browser. Nothing to install.

    Step 1 before any code: break the page into boxes¶

    Professional frontend developers never start by typing. They look at the design and draw boxes inside boxes. Each box becomes an HTML element; repeated boxes become a component (the same HTML + CSS reused). Here is FreshCart broken into its components:

    ① Announcement bar
    ② Logo ③ Location ④ Search box ⑤ Login · Cart (badge)
    ⑥ Category nav: All · Fruits · Vegetables · Dairy · … (scrolls sideways on a phone)
    ⑦ Hero banner: headline + button + picture
    ⑧ Offer ⑧ Offer ⑧ Offer
    ⑨⑨⑨⑨⑨⑨
    ⑩ Filters sidebar
    ⑪ Toolbar: "Showing 8 products" · Sort by
    ⑫ Product card⑫⑫⑫
    ⑬ Footer: about · links · newsletter
    ⑭ Cart drawer slides in from the right · ⑮ Bottom nav phones only

    Each number is one small component. Notice three things:

    • Components repeat. ⑫ Product card is written once and used eight times. ⑨ Category tile is used six times.
    • Components nest. The header ⑤ contains the cart button, which contains a red count badge.
    • Each component needs one layout tool. A row of things → Flexbox. A 2-D arrangement or a grid of equal cards → Grid.
    flowchart TD P["store.html"] --> A["① Announcement"] P --> H["Header"] H --> L["② Logo"] H --> LO["③ Location"] H --> S["④ Search"] H --> AC["⑤ Actions: Login + Cart button + badge"] P --> N["⑥ Category nav"] P --> M["main"] M --> HE["⑦ Hero + ⑧ Offers"] M --> C["⑨ Category tiles × 6"] M --> LI["Listing"] LI --> F["⑩ Filters"] LI --> T["⑪ Toolbar"] LI --> G["Product grid"] G --> PC["⑫ Product card × 8"] P --> D["⑭ Cart drawer"] P --> FO["⑬ Footer"] P --> B["⑮ Bottom nav"]

    Step 2: decide how it changes on a phone¶

    Write the phone layout first (one column, everything stacked), then add @media (width >= 768px) rules that spread things out on wider screens. This is called mobile first: phones get the simplest CSS, and big screens add to it.

    Component Phone (< 768 px) Desktop (≥ 768 px) Tool
    Header logo · location · cart on row 1, search on row 2 everything in one row Grid grid-template-areas
    Category nav one row that scrolls sideways one row, fits Flexbox + overflow-x: auto
    Hero text only text left, picture right Grid columns
    Offers swipeable carousel three equal boxes Grid + scroll-snap
    Category tiles 3 per row as many as fit Grid auto-fill
    Filters collapsed "Filters ▸" button always-open sidebar (≥ 900 px) <details> + Grid
    Product grid 2 per row as many as fit Grid auto-fill + minmax()
    Footer stacked 4 columns Grid auto-fit
    Bottom nav fixed at the bottom hidden position: fixed

    The lessons¶

    # Lesson You learn
    1 Page skeleton & design tokens Every line of the HTML boilerplate, a CSS reset, CSS variables, a .container, buttons
    2 Header & category nav Sticky header, grid-template-areas, a search form, a cart badge, a sideways-scrolling nav
    3 Hero, offers & category tiles clamp() font sizes, gradients, a scroll-snap carousel, an auto-fill grid
    4 Product card & product grid The most important e-commerce component: badge, price, ADD button, quantity stepper
    5 Listing: filters & sort Sidebar layout, <details>, <fieldset>, filtering and sorting with JavaScript
    6 Cart drawer <dialog>, ::backdrop, cart state, money in paise, event delegation
    7 Footer & mobile bottom nav Footer grid, newsletter form, position: fixed, :has(), safe areas
    8 Put it all together The assembled page, a testing checklist, and exercises to keep practising

    How each lesson is laid out¶

    1. What you see: the component, live, in a frame you can resize.
    2. HTML, then a line-by-line table explaining every line.
    3. CSS, then a line-by-line table.
    4. Try it exercises, each with a collapsed solution to open after you've had a go, and common mistakes. The code solutions all run together in store-solved.html.

    All code on these pages is pulled straight from the files in demos/, so what you read is exactly what runs in the frames. The <!-- --8<-- [start:…] --> comments you'll see in those files are only markers that tell this site which piece to show. You don't need them in your own copy.

    Why emoji instead of product photos?

    So the demo has no image files to download. In a real store each product picture is an <img>; lesson 4 shows exactly how to write it (width, height, alt, loading="lazy").
